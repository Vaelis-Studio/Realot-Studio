Quick start

  1. Open the hub and create a project. Start from a template (platformer, physics sandbox, flappy-bird style, top-down) or from an empty project.
  2. Open the editor. Select objects in the Hierarchy, change their settings in the Inspector, and arrange them in the Viewport.
  3. Add behavior with Add Component (physics, colliders, controllers, lights, audio, and more) and with Script components.
  4. Press Play to run the game in a separate window. Script errors and your console.log output show up in the editor's console.
  5. When it works, use Export to get a game you can host anywhere (see Exporting).

Your project autosaves in this browser. To back it up or move it to another device, use File → Save Project, which downloads a single .rs file (a ZIP archive with Realot's own extension). File → Load Project opens one again. If Realot is installed as an app, .rs files show the Realot icon and double-clicking one opens it in the editor; see file-association/README.md.

The code you see in the script editor is the code that runs. Scripts are stored once per project, and Play, Export and Save always use that stored code, even if an imported project's scenes carried an older copy.

Core concepts

  • Scene – a level or screen. A project can have several; switch with scene.load("Name").
  • Entity – any object in a scene. It has a name, optional tag, and a set of components.
  • Component – a piece of behavior or data on an entity: Transform, SpriteRenderer, ShapeRenderer, TextRenderer, SpriteAnimation, Rigidbody2D, Collider2D, CharacterController, Camera, Light, ShadowCaster, Tilemap, AudioSource, Joint2D, NavAgent2D, Joystick, Script, and others.
  • Tags – labels you put on entities so scripts can find or message groups of them (for example "Enemy").
  • Physics – powered by Rapier. Give an entity a Rigidbody2D and a Collider2D to make it physical. Physics layers decide what collides with what.

Scripting

Scripts are plain JavaScript attached to an entity with a Script component. You write functions with special names (called lifecycle functions) and the engine calls them at the right moments. Inside them, this is the entity the script is on.

function onStart() {
  this.speed = 200;            // your own variable on this entity's script
}

function onUpdate(dt) {
  if (input.keyDown("ArrowRight")) this.x += this.speed * dt;
  if (input.keyDown("ArrowLeft"))  this.x -= this.speed * dt;
}

Lifecycle functions

FunctionWhen it runs
onStart()Once, before the first onUpdate.
onUpdate(dt)Every rendered frame. dt is seconds since the last frame.
onFixedUpdate(dt)At a fixed 60 Hz step. Use for physics-style logic.
onClick()The frame the mouse or a finger is pressed on this entity (needs a Collider2D).
onCollisionEnter(other)This entity's collider starts touching another. (onCollision is an alias.)
onCollisionStay(other) / onCollisionExit(other)Every physics step while touching / when contact ends.
onTriggerEnter(other) / onTriggerExit(other)Entering / leaving a trigger collider.
onMessage(message, sender, data)Another script called sendMessage or broadcastMessage to this entity.
onClone()Only on entities created with spawn(), right before their onStart.
onDestroy()When the entity is destroyed or the scene ends.
onStateEnter() / onStateUpdate(dt) / onStateExit()Simple state machine: switch with this.state.change("name") and branch on this.state.current.
Arrow functions and this. Top-level function name() {} declarations get this bound to the entity automatically. Arrow functions can't be rebound, so a top-level arrow that uses this will not see the entity. The editor warns you when it spots one; use a normal function instead.

The editor's script editor has autocomplete for all of these, including the per-component members. Use it as the full reference.

Example: tween movement, rotation, and sprite opacity

function onStart() {
  // Animate several entity properties over 0.8 game seconds.
  tween(this, { x: 420, y: 180, rotation: 90, scaleX: 1.2, scaleY: 1.2 }, 0.8, "easeOutCubic", function () {
    // `this` is the entity that started the tween.
    tween(this.sprite, { opacity: 0.25 }, 0.35, "easeInOutSine");
  });

  // Save an id if you might need to stop an animation early.
  // var id = tween(this, { x: 700 }, 2, "easeOutBounce");
  // cancelTween(id);
}

Start a tween from a lifecycle callback such as onStart() or onClick(), rather than creating it every frame in onUpdate(). Properties must be numeric and already exist on the target; an entity supports x, y, rotation, scaleX, and scaleY, while component targets can animate their own numeric properties such as this.sprite.opacity. The editor autocompletes all supported easing names inside the easing string.

Example: a pickup that messages a score keeper

// On the coin
function onTriggerEnter(other) {
  if (other.tag === "Player") {
    sendMessage("GameController", "point");
    this.destroy();
  }
}

// On an entity tagged "GameController"
function onStart() { global.score = 0; }
function onMessage(message, sender, data) {
  if (message === "point") global.score += 1;
}

Slow motion and speed-up

time.scale changes how fast the whole game runs, like Unity's Time.timeScale.

function onClick() {
  time.scale = 0.3;              // slow motion
  wait(1.5, function () {        // 1.5 GAME seconds = 5 real seconds at 0.3
    time.scale = 1;
  });
}
  • Affected: physics, animations, tween(), wait() / repeat(), onFixedUpdate, time.deltaTime and time.elapsed.
  • Not affected: input, drawing, and time.unscaledDeltaTime. Audio keeps playing at normal pitch.
  • At 0 the game is frozen but scripts keep running: onUpdate is called with deltaTime = 0, so you can still read input and show a pause menu. Move menu animations with time.unscaledDeltaTime.
  • Limits: values must be numbers from 0 to 100 (anything else is ignored with a console warning). Each frame can simulate at most half a second of game time, so on a 60 FPS screen speeds above about 30x won't go faster.
  • It stays set when you load or restart a scene. Set time.scale = 1 yourself if the next scene should run at normal speed.

Saving data

Use save, not the browser's storage. Scripts can't use localStorage, window, document or fetch (see Safety).

var best = save.get("best") || 0;
if (global.score > best) save.set("best", global.score);

Also available: save.has, save.delete, save.keys, save.clear, and save slots through save.load, save.listSlots and save.deleteSlot.

Exporting

Open Export in the editor. You get a standalone .zip with an index.html at its root and no dependency on the editor.

  • HTML5 – a plain web game. Upload the unzipped folder to any static host (itch.io, GitHub Pages, Netlify, Cloudflare Pages).
  • PWA – the same game plus a manifest and service worker so players can install it and play offline.
  • Android APK – needs a build server. In the Export window add the server URL and API key supplied by whoever runs it. The editor sends your exported game to that server and downloads the finished APK. The APK itself runs without the server.
Don't open index.html straight from your disk. Browsers block ES modules on file://. Upload it, or run a local server in the folder (for example npx serve . or python3 -m http.server) and open the address it prints.

Exported games include THIRD_PARTY_LICENSES.txt. Keep it in the folder when you publish.

Troubleshooting

ProblemWhat to try
A script does nothingCheck the editor's console for a red error with the script name and line number. Make sure the script component is enabled.
this is undefined inside a functionYou used an arrow function at the top level. Use function name() { ... }.
"window is not defined" / "cannot read properties of undefined" on localStorage or fetchThose are blocked in scripts. Use save and global.
Collisions never fireBoth entities need a Collider2D, and at least one needs a Rigidbody2D. Check the physics layers.
Exported game shows a blank pageYou opened it from file://. Serve it over http(s).
"Autosave failed" / storage warningsThe browser's storage quota is full. Export a project .zip as a backup and remove unused assets.
Editor looks out of date after an updateReload once while online so the offline cache refreshes.

Safety

Scripts are code. A project's scripts run with the same permissions as the editor page, including access to anything saved in this browser (for example Android build server keys). Only open projects from people you trust. The editor asks before loading a project that contains scripts.

To limit accidents, scripts can't see window, document, localStorage, sessionStorage, indexedDB, fetch, XMLHttpRequest, WebSocket and similar globals. This is a safety net, not a security wall. The real protection is running games on a separate play origin from the editor, which whoever hosts Realot can set up (see SECURITY.md).
